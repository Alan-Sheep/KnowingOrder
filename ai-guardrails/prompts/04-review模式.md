# 提示词模板 04 · Review 模式（只报告不改）

> **用法**：想了解代码问题、或让 AI 评估方案时用。
> **核心：禁止任何写操作，只输出分析和方案。**
>
> 💡 **这是最安全的 AI 使用模式**，强烈建议多用。

---

## 模板 A：代码审查

```markdown
## 任务
请 review 这个项目，但**不要修改任何文件**。

## 你要做的
1. 读代码（`src/` 目录下的 Python 文件）
2. 找出问题，按严重程度分类：
   - 🔴 严重（会导致故障/安全问题）
   - 🟡 中等（影响质量/可维护性）
   - 🟢 建议（风格优化）
3. 对每个问题给出：
   - 文件路径 + 行号
   - 问题是什么
   - 为什么是问题
   - **建议的修改方案（用 diff 格式展示）**

## ⚠️ 重要
- 本次会话**禁止任何写操作**
- 不要新建文件、不要修改文件
- 只输出分析结果

## 完成后
等我挑选要改哪些，再一个一个来。
```

---

## 模板 B：方案设计（动手前先评审）

```markdown
## 任务
我要实现"检索结果缓存"，请你先出设计方案，**不要写代码**。

## 需要你回答
1. 缓存 key 怎么设计？（要考虑哪些变量）
2. TTL 设多少合适？不同类别的查询要不要不同？
3. 缓存放在哪一层？（工具层 / 编排层 / 两者都有）
4. 缓存穿透/雪崩怎么防？
5. 怎么监控缓存效果？（命中率怎么算）
6. 有哪些边界情况？

## 输出格式
- 用 Markdown
- 每部分给出理由，不要只给结论
- 如果有多种方案，列出各自的优缺点

## ⚠️ 本次会话禁止创建或修改任何文件。
```

> 💡 **先评审方案再动手**，能避免"写了 500 行发现方向错了"。

## 模板 C：排查问题（只诊断不修）

```markdown
## 问题
运行 `python -m src.main` 时报错：
```
[粘贴完整错误信息]
```

## 任务
1. 读相关代码，分析原因
2. 告诉我最可能的 3 个原因（按可能性排序）
3. 给出验证每个原因的方法（比如打印什么、跑什么命令）
4. **先不要改代码**

## ⚠️ 本次会话只做诊断，禁止修改文件。
等我确认原因后再决定怎么修。
```

---

## 模板 D：评估改动风险

```markdown
## 任务
我打算把 `src/graph/nodes/rewrite.py` 的查询改写逻辑
从"生成 1 个查询"改成"生成 3 个查询"。

请评估这个改动的风险，**不要动手改**。

## 需要你分析
1. **影响哪些文件/模块？**（列出具体路径）
2. **成本影响？**（搜索 API 调用会增加多少）
3. **性能影响？**（延迟会增加多少）
4. **有什么风险？**（如搜索额度、并发、错误处理）
5. **需要同步改哪些地方？**（配置、测试、文档）
6. **建议的实施方案**（分几步，每步验证什么）

## ⚠️ 只做分析，禁止修改任何文件。
```

---

## 为什么这个模式最安全

| 特点 | 收益 |
|---|---|
| **零写操作** | **不可能覆盖或乱码** |
| **先看方案** | 方向错了也只损失 2 分钟 |
| **你掌握决定权** | AI 只是顾问，不是执行者 |
| **可以随时中止** | 没有中间状态需要清理 |

> 💡 **建议的比例**：
> **60% 的时间用 Review 模式**（讨论方案），**40% 用于实际改动**。
>
> 新手常反过来——直接让 AI 改，然后反复返工。

## 进阶：把 Review 结果变成任务清单

Review 完之后，这样推进：

```markdown
好，我选这三个改：
1. [🔴] src/graph/nodes/search.py 缺少超时处理
2. [🔴] src/retrieval/cache.py 缓存 key 没包含 search_depth
3. [🟡] src/api/chat.py 输入长度没限制

请**一次只改一个**，每改完一个停下来等我确认。
从第 1 个开始：先 Read 文件，告诉我改动计划，等我确认后再动手。
```

## 附：让 AI 自查的提示词

有时 AI 改完后，让它自己 review 一遍也很有用：

```markdown
你刚才改了 `src/graph/nodes/rewrite.py`。

现在请你**只读不改**，自查这次改动：
1. 有没有引入 bug？
2. 有没有破坏原有的配置项？
3. 错误处理是否完整？
4. 中文注释是否正常？
5. 有没有改动到不该改的地方？

用 `git diff src/graph/nodes/rewrite.py` 看你的实际改动，然后回答。
```

> ⚠️ **注意**：AI 自查**不能替代你的检查**。
> 它经常说"一切正常"，但实际有问题。
> **最终以 `git diff` 和你自己的判断为准。**
