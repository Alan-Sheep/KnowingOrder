# 提示词模板 03 · 救火（改坏了怎么办）

> **用法**：发现 AI 改乱了文件时，**立即发第一段，不要继续对话**。
>
> ⚠️ **最重要的一条：先叫停，不要让它"再改一次修回来"。**
> 越修越坏是最常见的情况。

---

## 第一步：立即叫停

**复制这段，先发出去。什么都别做。**

```markdown
停。不要修改任何文件。

现在按顺序做这三件事：
1. 用 `git status` 告诉我当前工作区状态
2. 用 `git diff --stat` 告诉我改了哪些文件、各改了多少行
3. 停下来等我指示

⚠️ 在我明确说"继续"之前，禁止任何写操作。
```

> 💡 **为什么要先叫停**：AI 发现出错后，往往会"主动修复"——
> 而它的修复通常是**再重写一次**，把情况弄得更糟。

---

## 第二步：评估损失

**让 AI 汇报，你自己也看一遍：**

```markdown
请告诉我：
1. 这次会话你一共修改了哪几个文件？
2. 每个文件你做了什么操作？（精确编辑 / 整文件重写 / 新建 / 删除）
3. 有没有文件被整文件重写？
4. 有没有读取或输出过 .env 内容？

只回答，不要做任何修改。
```

**同时你自己执行**：

```bash
git status              # 哪些文件被改了
git diff --stat         # 改动的规模
git diff                # 具体改了什么
```

**判断损失程度**：

| 情况 | 严重度 | 处理 |
|---|---|---|
| 只改了 1-2 个文件，改动可控 | 🟢 轻 | 用 `git diff` 看，手工修或精确回滚 |
| 改了多个文件，但都是新增 | 🟡 中 | 逐个 review，保留对的 |
| 有文件被整文件重写 | 🔴 重 | **立即回滚该文件** |
| 出现乱码 | 🔴 重 | **立即回滚**，再单独处理编码 |
| 改了 `.env` 或泄露了密钥 | ⛔ 紧急 | **立即轮换密钥** |

---

## 第三步：回滚（推荐优先）

```markdown
我决定回滚。请你不要操作，只告诉我回滚命令。

我需要回滚：
- 全部改动 → 还是只回滚某个文件？
```

**你自己执行回滚命令**：

```bash
# 回滚所有未提交的改动（危险：会丢弃全部未提交内容）
git checkout -- .

# 只回滚单个文件（推荐，更精细）
git checkout -- src/main.py

# 回滚多个指定文件
git checkout -- src/main.py src/graph/nodes/rewrite.py

# 如果已经 commit 了，回滚到上一个提交
git reset --soft HEAD~1        # 保留改动，撤销提交
git checkout -- .              # 再丢弃改动
```

> ⚠️ **如果你改之前没 commit，`git checkout -- .` 会把你的改动也一起丢掉。**
> **这就是"改之前先提交"如此重要的原因。**

---

## 第四步：如果必须修（不能回滚）

**只在"回滚代价更大"时才走这条路。**

```markdown
不能整体回滚（那些改动是好的）。现在**只修 X 文件**。

## 问题
`src/main.py` 的中文注释变成了乱码，且文件从 400 行变成 180 行（内容丢失）。

## 要求
1. 先从 git 取回原文件：`git show HEAD:src/main.py > /tmp/orig.py`
2. 读取 `/tmp/orig.py` 和当前 `src/main.py`
3. **对比找出丢失的部分**，列给我看
4. **先不要改**，等我确认恢复方案

⚠️ 严禁整文件重写。如果需要恢复，请**分多次精确编辑**。
```

---

## 第五步：复盘（最重要，别跳过）

**把这次的教训写进 `AGENTS.md`**，避免再犯：

```markdown
请在 AGENTS.md 的"禁止清单"里加上这次的问题：

本次事故：整文件重写了 400 行的 main.py，导致内容丢失和中文乱码。
新增规则：
- ❌ 禁止对超过 100 行的文件使用整文件重写

只改 AGENTS.md 这一个文件，改完给我看 diff。
```

> 💡 **这一步是"企业级"和"作坊"的分水岭**：
> 每次事故都转化为一条**永久规则**，同类问题不再发生。

---

## ⛔ 紧急情况：密钥泄露

**如果 AI 读取、输出或提交了 `.env`：**

```markdown
停。你刚才可能泄露了密钥。

1. 立即停止所有操作
2. 告诉我：你把 .env 的哪些内容输出到了哪里？
3. 不要尝试"清理"，等我处理
```

**你必须立即做的**：

| 步骤 | 操作 |
|---|---|
| 1️⃣ | **立即到云平台轮换（重置）所有泄露的 API Key** |
| 2️⃣ | 检查 Git 历史：`git log --all --full-history -- .env` |
| 3️⃣ | 如果已提交到远程，**必须用 `git filter-repo` 清理历史**（仅删除文件不够，历史里还在） |
| 4️⃣ | 检查云平台账单，看有没有被盗用 |
| 5️⃣ | 设置每日额度上限，防止再次被盗刷 |

> ⚠️ **密钥一旦泄露，唯一的补救是"轮换"，不是"删除文件"。**
> 因为密钥可能已被读取、缓存、记录。

---

## 附：常见事故速查表

| 症状 | 原因 | 处理 |
|---|---|---|
| **中文变乱码（问号/方块/怪字符）** | 编码不一致 | `git checkout -- <file>` 回滚；设置 `PYTHONUTF8=1` |
| **文件行数突然变少** | 整文件重写 + 上下文截断 | **立即回滚**，改用精确编辑 |
| **注释没了** | AI 重写时丢弃了"不重要"的部分 | 回滚 |
| **代码格式全变了** | AI 顺手格式化了 | 回滚；在 AGENTS.md 加"禁止格式化" |
| **多出一堆 `.bak` / `.orig` 文件** | 工具留下的备份 | 删掉；确认 `.gitignore` 已忽略 |
| **整个文件显示为"全部改动"** | 换行符 CRLF↔LF 变了 | 加 `.gitattributes`，然后 `git add --renormalize .` |
| **出现了 `<<<<<<<` 标记** | 合并冲突没解决 | 手工解决或回滚 |
| **`.env` 被提交了** | `.gitignore` 没配好 | ⛔ **轮换密钥** + 清理 Git 历史 |

---

## 一句话总结

```
发现改坏了 → 立即叫停 → git diff 评估 → 优先回滚 → 复盘加规则

❌ 绝对不要：让 AI"再改一次修回来"
```
