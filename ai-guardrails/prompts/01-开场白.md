# 提示词模板 01 · 开场白

> **用法**：每次开新会话、或换一个新的 AI 工具时，**第一条消息就发这个**。
> 目的：让 AI 先读规则、建立优先级认知，再动手。

---

## 模板（复制下面这段）

```markdown
你要帮我改这个项目的代码。请先读 `AGENTS.md`（如果存在 `CLAUDE.md` 也读一遍），
然后确认你理解以下优先级和铁律。

## 优先级（冲突时按此裁决）
安全红线 > 不破坏现有内容 > 我的明确要求 > 项目规范 > 正确性 > 速度 > 风格

## 六条铁律
1. 禁止整文件重写超过 100 行的文件 —— 必须先 Read 再 Edit 精确替换
2. 编辑任何文件前必须先 Read 该文件
3. 一次最多修改 3 个文件，超过要分批
4. 只做我要求的最小改动，禁止顺手重构/格式化
5. 所有写文件必须 UTF-8，禁止改动文件编码
6. 不确定就停下来问我，不要猜

## 另外
- 不要读 `.env`（里面有密钥），需要参考请看 `.env.example`
- 不要主动 git commit / git push，除非我明确要求

## 现在请做
1. 读一遍项目结构（不要改任何文件）
2. 用 3-5 句话告诉我这个项目是做什么的
3. 告诉我你打算怎么遵守上面的规则

⚠️ 这一步只做调研和汇报，**不要修改任何文件**。
```

---

## 为什么这样设计

| 要素 | 作用 |
|---|---|
| **先读规则** | AI 的规则认知来自文件，不读就等于没有 |
| **明确优先级** | 冲突时有裁决依据，不会乱来 |
| **六条铁律** | 集中在最前面，注意力最强 |
| **禁止读 .env** | 防止密钥泄露到第三方 |
| **"只做调研不改文件"** | ⚠️ **关键**。第一步先建立信任，看它是否听话 |
| **让它复述规则** | 检验它是否真的理解了 |

---

## ⚠️ 一个重要的验证技巧

**第一条消息故意只让它"读和汇报"，不让它改文件。**

- ✅ 如果它老实汇报、没动任何文件 → 这个 AI 可以信任，继续用
- ❌ 如果它"顺手"就把代码改了 → **这个工具很危险，要加强约束或换工具**

> 这叫**"信任但要验证"**。花 2 分钟做这个测试，能避免后面一天的返工。

---

## 如果 AI 说"我读了 AGENTS.md"

**不要只信它的说法。** 用这个追问验证：

```markdown
请用你自己的话告诉我：
1. AGENTS.md 里的优先级顺序是什么？
2. 一次最多能改几个文件？
3. 遇到"重写这个 500 行文件"的要求时，你应该怎么做？
```

如果它答不上来或答错，说明**它没真读**（或上下文被截断了）。

> 💡 这种情况下，**把关键规则直接贴在消息里**，不要依赖它去读文件。

---

## 配合使用的文件

确保项目根目录有这些文件：

```
你的项目/
├── AGENTS.md          ← 必须有（通用规则）
├── CLAUDE.md          ← Claude Code 用
├── .editorconfig      ← 编码统一
├── .gitattributes     ← 换行符统一
├── .gitignore         ← 忽略清单
└── scripts/
    └── check_encoding.py   ← 检查脚本
```

这些文件都在 `ai-guardrails/` 里，复制过去即可。
