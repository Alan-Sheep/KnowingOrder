# 学校业务范围识别与问答分流实施记录

日期：2026-10-24。范围：承接已完成的KnowledgeScopeContract，接通范围识别、正式回答路由、持久结果兼容和Vue反馈。学校仍复用企业/成员/空间模型，没有改表、下载模型、安装依赖或修改密钥。下面的结果均区分代码、离线验收与真实语义效果。

## 1. 为什么用这个方法，可以用什么替代

采用“服务端组织范围＋一次结构化模型识别＋程序校验＋原授权检索”。范围回答的是“问题属于什么业务”，向量相似度回答的是“文字语义接近程度”，授权回答的是“能不能读”，证据充分性回答的是“这些资料能不能支持结论”；四者不能互相替代。

- 不用“宠物保险”禁词：本校开设宠物保险课程仍属于课程业务，关键词会误拒。当前学校范围固定为school:v1，只对服务端明确配置的组织启用，不强制其他租户采用学校范围。
- 不以向量是否命中判断业务归属：范围内可能缺资料，范围外也可能误召回相似条款。原K07实际混合召回的是培训补贴；“宠物保险引用餐补”是离线故障注入，两者不能混说。
- 不为每个子问题各调用一次模型：先识别，再把校内问题批量生成一次；最多3分项、共享6段授权证据，避免三问变成三轮串行计费。代价是多个校内问题共享召回窗口，不能保证每项都有候选。
- 不新增Guardrails框架：复用现有ChatModel、版本注册、严格JSON和TaskDeadline即可完成本单元。已尝试GitHub开源方案检索，但本轮工具未返回可核验正文，没有引用未经核实的实现或增加依赖。

这是业务分流，不是另一个答案审核器。模型可能把业务归属判错，程序的摘要、字段、分段校验只能验证格式和输入一致性，不能证明标签语义正确。

## 2. 怎么做，代码与数据怎样流转

调用顺序：原登录与空间核权 → 核对服务端学校组织名单 → 核对合成空间外发许可 → 范围识别 → 重核当前权限 → 校内原问题拼接检索 → 一次固定分段生成 → 与校外/未知分项按原序合并 → 再核权和证据快照 → 原接口返回/持久任务保存 → Vue严格解析。

1. `KnowledgeScopeResolver.resolve()`，第39行：生成本次UUID，绑定组织/成员/空间、school:v1完整定义、当前问题及可信追问。对模型只发送snapshotId、范围和问题，不发送身份编号或文档；可信历史另放antecedentQuestion，不混入当前原文。
2. `knowledge-scope:v1`输出snapshotId和1—3个question/scope；既有契约要求连续片段逐字拼回输入，不能丢空格、标点、否定或后半问。服务入口保留既有首尾strip行为，契约针对进入识别器的文本校验。
3. `KnowledgeAnswerService.scopedAnswer()`，第140行：OUT_OF_SCOPE与UNKNOWN不检索、不生成；IN_SCOPE进入原evidenceAnswer路径。检索总计最多6段；可信追问允许第二路原话题检索，仍受同一授权与总上限约束。
4. `KnowledgeAnswerComposer.composeFixed()`，第34行：payload增加questions数组，使用knowledge-scoped:v1。生成结果必须与数组的数量、原序和原文逐字相等；连续引文、sourceId、段落和资料冲突契约沿用旧实现。原compose接口及旧模板保留。
5. `scopeStatus()`，第194行：分项相同直接保留；冲突优先；确有生成答案时混合结果为PARTIAL；否则保留故障/未知/摘录/不足，避免“校外＋未知”被说成“部分可回答”。分项始终完整展示。
6. 原持久任务保存已校验的Answer JSON，无需新表。COMPLETED仅表示任务处理结束，分项仍可能范围外、无资料或失败；刷新读取不再次运行分类器，引用仍按当前权限复核。范围版本还没有单独作为结果字段持久化，这是审计扩展待办。

调用数说明：这里的“一次识别＋一次生成”只描述范围模块及回答阶段。若另外启用既有多轮追问关联，它可在此前增加候选与复核两次调用（两次共用5秒阶段）；整条链路仍共用原任务30秒，不能宣称所有情况下总共只有两次模型调用。

以下是实际离线替身用例的数据，不是付费模型结果：

```text
输入：奖学金多少？宠物保险怎么买？多久到账？
固定识别结果：IN_SCOPE / OUT_OF_SCOPE / IN_SCOPE
检索输入：奖学金多少？多久到账？
虚构原文：奖学金每人1000元。
返回顺序：1 ANSWERED（每人1000元，带原文引用）
          2 OUT_OF_SCOPE（提示主动切换）
          3 NO_EVIDENCE（缺少到账时间）
调用次数：范围识别1次＋回答生成1次，不重试。
```

## 3. 会遇到什么问题，如何处理

| 情况 | 当前处理与限制 |
|---|---|
| 没有获准的外发空间 | 配置了学校组织也返回SCOPE_UNAVAILABLE；问题、历史和资料不外发，不检索、不生成。未配置学校组织则保持原流程。 |
| 范围归属不确定 | SCOPE_UNKNOWN，不断言学校没有规定，不伪装成NO_EVIDENCE，不强迫用户给处理优先级。 |
| 分类超时、空值、非法标签、重复键、尾随JSON、错摘要或漏问题 | SCOPE_UNAVAILABLE，可见提示且零自动重试；总预算耗尽则沿用原超时终态，不续时限。 |
| 校内没有候选 | 每个校内分项NO_EVIDENCE，校外/未知项保留；不从其他业务条款挪用金额。 |
| 分类成功后生成改写了问题边界 | MODEL_UNAVAILABLE；保留可核对的授权原文，不接受悄悄合并、漏问或重排。 |
| 识别期间或生成期间撤权 | 再核当前成员、空间和证据；拒绝返回旧结果，分类标签不能充当授权凭据。前后重核不是跨系统原子快照。 |
| 多问并发、断线或刷新 | 复用原2执行者/无排队/30秒预算，以及持久任务幂等、取消和查询；不因分类新建无界线程或重提任务。本模块不新增数据库写事务。 |
| 用户想转公开问答 | 只有范围外分项显示按钮；事件不带参数，仅导航，不复制问题、学校资料或历史，不发公开提问。公开服务是否可用仍独立验收。 |
| 日志或异常泄露 | 新日志仅状态、分项数、证据数和耗时，沿用请求标识；不记录用户正文、资料、供应商响应或凭据。 |
| 结构正确但业务误判/答案无据 | 仍可能发生，不能以离线通过冒充解决。原有“真实引文支持不了错误结论”特征测试保留，7条改写漂移与校内误召回继续待办。 |

识别阶段最多5秒、2000输出Token，生成最多3000输出Token；全部共享原30秒。5秒是防分类占满预算的初始工程上限，不是已测得的最优值。极长或复杂问题可能输出截断/超时，本次会失败可见，不静默截断用户问题。取消本地等待不承诺第三方已收到的请求不计费。

## 4. 能否优化，怎么优化及代价

| 优化方向 | 做法与代价；以下均尚未实现 |
|---|---|
| 真实分类质量 | 固定学校合成调参集与留出集，分别统计校内误拒、校外误放、UNKNOWN率、混合逐项完整率及p95；不把手填标签算准确率。需批准真实模型预算。 |
| 降低时延和外发成本 | 可换本地轻量分类器或本地生成模型；需要模型部署、内存、中文评测与协议适配，现有bge-m3仅是Embedding，不能直接替代生成分类器。 |
| 安全缓存 | 键须含组织、范围版本及完整定义、当前问题和可信上下文；需容量/TTL、隐私隔离和权限重核，不能仅按问题缓存跨租户复用。目前无新缓存或Redis。 |
| 多校内问题召回公平性 | 分问题有界检索后去重融合，给每项保留候选名额；数据库/向量请求数和延迟会上升，仍须共享总时限及证据上限，先按黄金集验证必要性。 |
| 可运营范围与审计 | 范围配置后台、版本快照持久化、变更权限与审计；涉及数据模型及管理流程，当前仅服务端学校名单和固定school:v1。 |
| 证据语义支持 | 先排查召回/分块/版本，再比较精排、声明级证据检查或额外审核模型；额外调用也会误判并增加时延成本，不在本模块暗加。 |

知识点：结构化意图路由、纯契约与完整输入绑定、服务端可信配置、权限与业务范围分离、共享截止时间、批量生成、引用溯源、显式降级、任务终态与回答状态分离、Vue类型校验与无载荷事件。没有新增MCP、OCR、Redis、向量服务或模型下载。
