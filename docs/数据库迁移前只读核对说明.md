## 本单元为什么先做

已有库可能是原基础结构、完成01、完成02、部分执行03或完整新结构。看到新增表不能直接断言迁移完成，直接重放空库schema又可能与已有对象冲突。先检查目标和实际结构，才能选择后续动作。

只读脚本：[20261018_enterprise_preflight.sql](../backend/sql/checks/20261018_enterprise_preflight.sql)。对照源码：[01](../backend/sql/migrations/20261017_01_guest_identity.sql)、[02](../backend/sql/migrations/20261017_02_guest_lifecycle.sql)、[03](../backend/sql/migrations/20261017_03_enterprise_membership.sql)以及[空库schema](../backend/schema.sql)。

## 怎么运行

1. 在IDEA的Database工具窗口打开原MySQL数据源，确认是你要操作的本地开发库；不用把连接串、账号或密码发送到对话。
2. 打开该数据源的Query Console，选中目标库。先只执行脚本第1段；`selected_database`应是预期开发库，产品应为MySQL，版本至少8.0.16。其他数据库或更旧版本不在本脚本的适用范围内。
3. 确认后逐段执行第2—6段。可以反复运行这些查询；不能把同样操作方法套用于只允许执行一次的01/02/03迁移。
4. 对照脚本原文核对定义。元数据不够可见时先确认连接账号权限，不能把全部“缺失”直接当作空库。

IDEA控制台选中语句后使用执行按钮或`Ctrl+Enter`。这里不增加Web接口、不启动Spring应用、不读取IDEA运行配置或`.env`。脚本无`USE`，不会替你切换库。

## 看到结果后怎么判断

| 结果 | 下一步 |
|---|---|
| 目标库未选、版本不符或SQL报错 | 停止；先核对数据源、版本与可见权限。 |
| 原有基础表都没有 | 核对是否空库及是否连错库；空库初始化必须另外确认，不直接跑03。 |
| 01/02前置缺失 | 定位实际进度并评审对应前置迁移；当前访客功能冻结不等于既有迁移前置被自动补齐。 |
| 01/02前置符合，03对象全部缺失 | 可以进入03迁移评审；备份与执行授权仍需确认，脚本不会自动执行它。 |
| 03部分对象存在，或对象定义不符 | 按部分执行或结构漂移处理；停止并制定精确修复，禁止盲目重跑整份03。 |
| 预期对象均存在且定义已人工匹配 | 仅说明检查覆盖的结构匹配；另核对完整原表、旧数据及备份，不能推出03历史执行记录、回填、事务、锁和首次管理员已验收。 |

示意结果：`sys_user.auth_version`显示“缺失或不可见”只是提示，不表示已知原因；`uk_enterprise_user`只有列顺序为`enterprise_id,user_id`且唯一、无前缀、可见、BTREE及升序时，才显示“索引定义匹配”。以上是结果解释，不是本轮真实数据库输出。
