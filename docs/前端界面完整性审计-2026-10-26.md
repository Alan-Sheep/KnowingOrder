# 前端界面完整性审计

> **审计日期**：2026-10-26
> **审计范围**：`frontend/src` 全部 13 个组件、9 个接口客户端、`App.vue` 路由层；对照后端 20 个控制器、85 个 HTTP 端点。
> **审计方式**：① 接口层方法 × 组件调用点做静态交叉比对；② 用 CDP 以已登录管理员身份逐页渲染，抓未捕获异常、失败请求、全部交互控件；③ 对可疑缺陷构造定向 mock 复现。

---

## 一、结论先说

**不是「大量没接后端」，而是「接口接得很全，韧性不足、少数缺口、观感拖后腿」。**

企业客户端共封装 **71 个方法**，**70 个有真实调用点**（仅 `parseVersion` 无人调用）。真正的问题分布是：

| 类别 | 数量 | 影响 |
|---|---|---|
| 功能性缺陷（会导致看不到数据） | 2 | 高 |
| 体验/一致性问题 | 4 | 中 |
| 后端有、前端无入口 | 5 | 中低 |
| 环境与文案问题 | 3 | 低 |

## 三、P0：会导致「明明有数据却看不到」

### 3.1 员工事务页：一个接口失败，后面 5 个接口一个都不发

`AffairsPanel.vue:167` 的 `reload()` 是纯串行 `await`，且没有逐个 `try/catch`：

```ts
async function reload() {
  await loadRules();                          // ① 任一异常 → 直接抛出
  await loadMembers();                        // ② 不会再执行
  await loadMine(minePage.value);             // ③
  await loadPending(pendingPage.value);       // ④
  if (isStaff.value) {
    await loadFinance(financePage.value);     // ⑤
    await loadSettlements(settlementPage.value); // ⑥
  }
}
```

**实测复现**：只让 `/affairs/rules` 返回格式错误，其余接口返回正确数据 —

```
请求到的 affairs 接口顺序：
  /api/enterprises/1/affairs/rules      ← 只有这一个
「我的申请」是否出现记录：false
页面提示：补贴规则列表响应格式不正确，请核对后端版本。
```

后果：**规则表格式一变、或该接口超时，员工的「我的申请」「待我确认」「财务协同」「结算」全部空白**，即使这些数据完好无损。员工会以为自己的申请丢了。

**对比**同一项目的另外两个面板，说明这不是设计取向问题，而是遗漏：

- `KnowledgeAnswerPanel` 对 `answerMode` / `retrievalMode` / `chats` 各自独立 `try/catch`
- `KnowledgeDocumentsPanel` 对 `grants`（降级为只读）、`loadCandidates`（降级为空列表）都独立捕获

**修法**：改成 `Promise.allSettled` 或逐段 `try/catch`，把失败限制在对应区块，并在该区块内单独提示。

### 3.2 工作台零数据驱动

以已登录管理员进入工作台，**发出 0 个接口请求**。三张「你的工作捷径」卡片、引导、状态区全部是硬编码模板。

新员工登录后最想知道的四件事——我有几个知识空间、有哪些资料、有几条待我确认的补贴、上次问到哪了——一个都没有。而这些数据在其它四个页面都已具备。

**修法**：工作台至少接三个只读接口（`knowledge-spaces`、`affairs/confirmations`、`workspace/chats`），做成「我的空间 / 待我确认 / 最近提问」三张真实卡片。这是投入产出最高的一条。

## 四、P1：体验与一致性

### 4.1 `PREVIEW` 开发标记常驻所有页面

`App.vue:282` 硬编码 `<span class="beta-label">PREVIEW</span>`，紧跟面包屑，**五个页面全部显示**。配合顶栏右侧的「● 本地开发」状态标签，整站从头到尾都在向访客宣告「这是没做完的东西」。对外演示时必须摘掉或改为按环境变量控制。

### 4.2 三个页面各有一份独立的登录态和登录表单

| 文件 | 行为 |
|---|---|
| `KnowledgeAnswerPanel.vue:303` | 自己 `api.me()`，未登录只显示「登录并开始」跳转按钮 |
| `KnowledgeSpacePanel.vue:54,69,122` | **完整登录表单**（`#enterprise-username`）+ 自己 `me()` + `logout()` |
| `AffairsPanel.vue:146,159,390` | **另一份完整登录表单**（`#affairs-username`）+ 自己 `me()` + `logout()` |

三份实现互不知情。当前靠「页面切换时组件卸载、重新 `me()`」掩盖了大部分问题，但：

- 同一功能有两套输入框 ID、两套错误处理，改一处漏两处；
- 退出登录只清当前组件的 `user` ref，其它已挂载面板的状态不刷新；
- 换页面会先闪一下未登录态（`me()` 未返回前）。

**修法**：抽一个 `useSession`（或 Pinia store）统一持有 `user`、`login`、`logout`，三个面板只读同一个状态。

### 4.3 危险操作仍用浏览器原生 `window.confirm`

共 5 处：

| 位置 | 操作 |
|---|---|
| `KnowledgeDocumentsPanel.vue:265` | 重建草稿片段 |
| `KnowledgeDocumentsPanel.vue:419` | 撤回 / 删除文档 / 删除版本 |
| `OrganizationPanel.vue:83` | 停用部门 |
| `OrganizationPanel.vue:94` | 变更成员部门或状态 |

原生 `confirm` 在 Windows 上是系统级灰色弹窗，与全站精心设计的界面完全割裂。而**会话删除已经做过内联二次确认**（`KnowledgeAnswerPanel` 的 `confirmDelete`），说明团队已经意识到这个问题，只是没推广到其它四处。

### 4.4 错误提示是开发视角文案

员工看到的原文：

> 补贴规则列表响应格式不正确，请核对后端版本。
> 向量接口响应格式或资源绑定不正确，请核对后端版本。
> 入库任务响应格式不正确，请核对后端版本。

「响应格式不正确」「核对后端版本」是给开发者看的。普通员工既不知道什么叫响应格式，也无权核对后端版本。这类文案应改成「暂时读不到补贴规则，请稍后重试或联系管理员」这类可行动的说法，技术细节留在 `console`。

## 五、P2：后端有接口，前端没有入口

| 接口 | 现状 | 建议 |
|---|---|---|
| `POST /api/auth/revoke-sessions` | 无任何调用 | **值得补**：改密面板加「下线我的全部设备」，账号疑似泄露时的应急手段 |
| `GET .../workspace/capabilities` | 无调用 | 前端靠「`chats()` 调用成功」反推持久任务能力，多一次全量请求；改用该接口显式协商 |
| `POST .../documents/{id}/versions/{vid}/parse` | 封装为 `parseVersion` 但无人调用 | 已被入库任务（`submitIngest PARSE`）取代，属死代码，可删 |
| `POST /api/enterprises/{id}/employees/{memberId}/status` | 未封装 | 与 `organization/members/{id}` 的 `status` 字段功能重叠，确认后择一保留 |
| `EnterpriseResourceController` 全 6 个接口 | 全站零调用 | `conversations` / `messages` / `knowledge-spaces` / `documents` / `tasks/reference` 是上一代只读入口，已被 `knowledge-workspace` + `knowledge-documents` 取代。服务层 `EnterpriseResourceService` 仍被检索链路重度使用，但 HTTP 壳是僵尸接口 |

## 六、P3：环境与文案

### 6.1 两个入口依赖 dev-only 接口，界面不随环境隐藏

`WebChatController`（`/api/chat`）与 `ProductSearchController`（`/api/products/search`）都带 `@Profile("dev")`。后端默认 profile 是 `dev`，所以现在可用；一旦以 `--spring.profiles.active=prod` 启动，这两个接口直接 404，但界面上的「联网问答体验」和「商品查询」按钮照常显示。

前端已对 404 做了提示（「商品接口尚未启用，请重启最新版 dev 后端」），但仍是**先让用户点进去再告诉他不可用**。

### 6.2 「企业知识问答 · 需登录」文案与登录状态不同步

联网问答页输入框工具栏上的切换按钮（`App.vue:341`）写死 `需登录` 标签。无论用户是否已登录，都显示「需登录」。已登录用户会困惑。

### 6.3 窄屏（900px）侧栏不折叠

900px 宽下侧栏仍占 226px（约 25%），主内容被压到 674px。底部「企业账号与空间」被挤成两行。不算功能问题，但演示用小屏时会显得拥挤。全站无横向溢出，这点是对的。

## 七、建议的修复顺序

| 优先级 | 事项 | 成本 | 收益 |
|---|---|---|---|
| 1 | 事务页改 `Promise.allSettled`，失败按区块隔离 | 小 | 消除「申请凭空消失」 |
| 2 | 工作台接三个只读接口做真实卡片 | 中 | 登录后第一眼有内容 |
| 3 | 摘掉 `PREVIEW`、`本地开发` 标识改按环境显示 | 极小 | 演示观感 |
| 4 | 5 处原生 `confirm` 换成内联确认 | 小 | 与已有会话删除对齐 |
| 5 | 错误文案去技术化 | 小 | 员工可理解 |
| 6 | 抽统一会话 store，合并两套登录表单 | 中 | 消除三份状态 |
| 7 | 补「下线全部设备」入口 | 小 | 补齐一条已有后端能力 |
| 8 | 清理僵尸接口与死代码 | 小 | 减维护负担 |
