## 3. 会话与任务：四方面及知识点

**为什么选它、替代什么**：已有MySQL能够持久保存业务状态，采用表＋有限轮询，不为当前单节点增加Redis/MQ。只在浏览器内存保存会话会在刷新后丢失；断线后自动新POST则可能重复付费。数据库保存状态不能独自保证模型“恰好执行一次”，因此RUNNING重启后不自动重放。

**代码与数据怎么走**：`KnowledgeWorkspaceService.submit()`（约106行）校验UUID/文本→服务端身份与空间→事务锁成员行→查原请求→限额→会话/任务同事务写入。`dispatch()`（约79行）每秒取最多两条PENDING；`execute()`（约164行）通过`claim()`的条件更新取得执行权→重新核权→answerWithin接收原deadline减当前时刻→保存终态。Mapper约18行OWNER同时限定企业、成员、账号和空间，约21行JOB_COLUMNS显式排列record构造参数。

真实测试输入为`Submit(UUID, UUID, "餐补多少，谁审批？")`：第一次返回PENDING和30秒截止，重复同参数返回同一任务；换问题返回409。两个线程同时提交同UUID只落一个任务；已有一个在途时再并发两个，仅一个受理、一个503。它们是隔离H2上实际执行的SQL断言，不是MySQL锁行为验收。

**问题与解决**：PENDING重启可继续，RUNNING只等原deadline结束，不猜上游结果；取消先写CANCELLED再中断本地等待，迟到结果的条件更新不能覆盖。断网/刷新仅停进度连接，页面重新选择空间读取原历史。提交响应丢失时先GET原任务，查到就不POST，明确404后才允许人工按原UUID/问题重发；服务故障或网络失败不作为“未受理”依据。两条独立问题并行，不自动合并，也没有实现依赖图调度或历史指代解析。

**优化与代价**：每成员上限在成员行锁内判断；全局64条计数只是粗准入，不是跨成员/跨节点严格原子配额。后续需据压测评审独立配额行/信号量、多节点租约和故障恢复；不能只加Redis锁就声称避免所有重复调用。每次历史读取复核引用，会增加数据库查询；最近50个会话及每会话50条历史是当前有界读取，老数据未删除，完整游标分页和保留期限待补。任务30秒不等于任意数据库/磁盘故障都能在30秒硬中断，真实SQL等待与容量仍待验。

**知识点/服务**：SQL参数绑定、事务回滚、行锁、UUID幂等、CAS（只在预期旧状态成立时更新）、有界执行器、持久状态机、轮询恢复、单调时钟阶段预算、MDC线程日志上下文。任务UUID作为后台request_id，日志只记编号、耗时预算、状态/应用标记和安全错误码，不输出问题、原文或第三方错误正文。不是MCP、多Agent或向量检索。

## 4. 反馈与安全历史：四方面及知识点

**为什么选它、替代什么**：将“模型回答是否正确”变成可追溯的知识维护事项，关联本人已完成任务和可选实际引用；管理员身份不自动获得其他员工私有会话。自动把员工反馈写回制度会污染知识，因此只有维护者填写处理说明，不自动改发布版本。

**代码与数据怎么走**：`feedback()`约224行验证COMPLETED、引用属于本次可读回答，UUID防重复；Mapper的反馈查询只连接对应企业/空间/成员的任务。`feedbacks()/resolve()`约247/255行必须获得明确MAINTAIN授权；处理条件为`OPEN AND revision=请求版本`，成功revision加一。Vue反馈组件展示关联原问题和处理说明，不向维护者开放整段会话。

**问题与解决**：伪造chunkId拒绝；相同反馈编号换内容409；两个处理者用旧revision不能覆盖新处理。前端第一次发送后冻结反馈内容，结果未知仍以同UUID/内容核对，不让修改文本变成换参重试。`view()`约192行对已存引用逐条重新授权并比较完整快照；资料撤回、更新或不可读时隐藏整份旧回答，不用数据库历史正文绕过权限。

**优化与代价**：当前读取最多100条反馈，完整分页、通知、去重合并与SLA后续评审。历史保存完整应用结果增加磁盘和权限复核成本；以后可拆引用快照和正文，建立保留期/清理审计。撤权无法收回用户此前已经看见或截图的内容，也无法撤回已发到获准模型的数据。

**知识点/服务**：最小权限、数据行范围隔离、乐观锁、人工协同、来源快照、版本有效性、XSS纯文本输出、NoPayloadLog。Session负责可信身份，CSRF保护浏览器写入；ThreadLocal/MDC只传播线程上下文，不提供身份授权。

## 5. 本机Embedding与准入：四方面及知识点

**为什么选它、替代什么**：用户要求暂不下载模型，又禁止默认外发真实企业原文，因此只实现可配置的本机Ollama协议适配器。与立即安装完整向量框架相比，先固定输入输出和故障契约；与硬编码假向量相比，关闭时明确不可用，不伪造成功。

**代码与数据怎么走**：`TextEmbeddings.embed(texts, deadline)`返回不可变向量；`LocalEmbeddingClient.embed()`约53行校验1—16条/每条最多1200字符→`POST /api/embed`传`model/input/truncate:false`→校验JSON、模型、数量、同批维度和有限非零向量。单向量最多2048维、响应2MiB、连接2秒、阶段5秒并受父任务剩余预算限制；无重试、无拉模型请求。例子`["虚构餐补制度"]`由本机HTTP替身返回`{"model":"synthetic:1","embeddings":[[0.3,0.4]]}`，仅证明传输/格式，不证明语义效果。

**问题与解决**：地址只收HTTP字面回环127.0.0.1或[::1]根地址，拒绝公网、localhost、凭据、额外路径/参数与重定向；401/403/404/429/5xx、空/错误结构、不同维度、超大响应及慢响应均失败且不重试。输入控制字符和孤立代理项在HTTP前拒绝。回环限制用于当前本机部署；容器服务发现、远程推理及TLS须单独评审，不靠放宽白名单绕过数据边界。

`KnowledgeEvidenceAdmission.decide()`约23行先验证两路全部快照，再验证绑定的原问题/备选句；只有原意PASS且单条适用ACCEPT才加入已有最多6段融合。UNKNOWN/BLOCK/错绑不采纳补充，保留基线仍不代表足以回答。显式测试判定只验证组合，未新增自动语义识别，7条词法漏检仍保留。

**优化与代价**：后续用户自行选择轻量中文Embedding或Ollama模型后，验证真实维度、模型版本、切块长度/Token截断、中文召回、内存和P95，再接入索引/权限过滤及混合召回。当前字符上限不保证适配每个模型的Token上限，truncate:false要求超限显式失败。不能把适配器测试或手填PASS/BLOCK称作RAG质量提升。真实改写预算和企业外发许可仍待确认。

**知识点/服务**：适配器模式、Embedding文本向量化、HTTP总预算、响应体上限、协议严格校验、SSRF边界、RAG召回与生成分离、语义漂移与保守准入。本轮没有新增MCP、Redis、MQ或真实向量库。

## 6. API与失败行为

统一前缀：`/api/enterprises/{enterpriseId}/knowledge-spaces/{spaceId}/workspace`。统一Result，身份只取Session，POST要求当前CSRF，客户端身份字段不提供授权。

| 方法和路径 | 输入与输出 |
|---|---|
| GET `/chats` | 本人最近50个会话 |
| GET `/chats/{chatId}` | 本人该会话最近50条任务；历史回答重核引用 |
| POST `/jobs` | `{"chatId":"UUID","requestId":"UUID","question":"问题"}`；返回受理或原任务 |
| GET `/jobs/{id}` | 原任务状态、首次截止、可读结果及用户可见说明 |
| POST `/jobs/{id}/cancel` | 幂等结束本人在途任务，终态不再覆盖 |
| POST `/feedback` | `id/jobId/chunkId(可空)/category/comment`；类别INCORRECT/MISSING/OUTDATED/OTHER |
| GET `/feedback` | 仅空间维护者读最近100条反馈与对应原问题 |
| POST `/feedback/{id}/resolve` | `{"revision":1,"status":"RESOLVED","resolution":"核验说明"}`；也可DISMISSED |

400非法输入；401失效登录；404不存在或无权；409编号换参/状态变化；503在途超限或服务暂不可用；任务TIMED_OUT为持久状态。进度每秒查询，页面单次循环最多35秒；失败停止等待并提示手动核对，不把服务失败当作没有资料。
