## 2. 四项模块的学习记录

### 2.1 企业与成员模型

**为何这样选**：`sys_user`说明账号是谁，`sys_enterprise_member`说明账号在某企业的关系。同一账号可以属于不同企业，成员编号和角色分别独立。没有把企业字段直接塞进账号表，也没有共用“匿名员工”；这样不会把账号在甲企业的身份沿用到乙企业。

**代码与数据如何流转**：`SysEnterprise`、`SysEnterpriseMember`映射企业/成员。`EnterpriseDirectoryMapper`联合企业、成员、账号读取；不可变`EnterpriseMemberContext`保存企业/成员/账号编号、直属部门、角色、企业权限版本、成员权限版本和账号认证版本。上下文只在服务端内部流转。

**问题与解决**：旧记录缺少企业归属，不能自动归入第一家企业；新增归属字段允许为空，企业入口不匹配这些旧记录。成员唯一约束为`(enterprise_id,user_id)`，停用/离职更新同一成员；不插入第二条关系绕过旧状态。没有物理外键，跨表关联和企业一致性由授权SQL、事务及后续写服务负责。

**还能怎样优化**：先保留直属部门的平级授权，不隐式继承父部门。组织层级、角色组合、成员调动和更细资源权限后续单独增加；权限缓存必须包含企业和版本并能撤权，不能只按用户或问题文本缓存。

### 2.2 有效成员与版本复核

**为何这样选**：身份认证、成员关系、资源权限分别负责不同问题。一次登录不能保证员工仍在职；ThreadLocal只能传递信息，不能产生权限。首版每次查询数据库，不提前引入缓存或把客户端成员编号当成证明。

**代码与数据如何流转**：`EnterpriseMemberServiceImpl.requireMember()`先调用`CurrentUserService.requireUserId()`，再绑定账号、企业及原认证版本查询有效关系。`requireCurrent()`重新取得关系并比较完整上下文。资源SQL再次绑定有效账号、成员、企业和版本，避免只做前置检查后无范围地按主键读取。

**问题与解决**：发现“账号复核后、成员查询前撤销登录”的竞态；若成员查询直接读新版本，旧登录可能被升级成新身份。现在两次查询始终绑定原认证版本，返回上下文也要匹配它。企业停用、成员停用/离职、账号停用/删除、版本变化均拒绝；数据库故障不返回默认成员。

**还能怎样优化**：后续异步执行、检索、模型外发、引用和下载前复用这些入口。缓存或长事务不能保证任意时刻的实时撤权，必须定义失效和提交边界；已经发出的数据无法收回。首版资源读取不包裹长事务。

### 2.3 真实登录与管理员开户

**为何这样选**：采用Spring Security标准表单认证和服务端会话，复用密码核验、认证上下文、登录换会话编号、退出和CSRF机制；没有自己编写长期JWT的签发/撤销逻辑。已有企业SSO以后可替换身份接入，资源授权服务仍保留。

**代码与数据如何流转**：`AccountLoginService`参数化查询正常、未删除账号，`AccountDetails`携带稳定账号编号及认证版本，密码认证后由框架擦除。后续请求由`SessionIdentityFilter`复核期限、状态和认证版本。控制器通过`@AuthenticationPrincipal`取得框架身份，不接收`userId`、角色或成员请求头。

管理员开户走`EnterpriseAccountServiceImpl.createEmployee()`：复核管理员并加锁 → 校验输入 → BCrypt散列 → 插入账号 → 插入员工成员关系 → 同一事务提交。第二次写失败必须回滚第一次写。新账号名3至64位字母、数字或`_.@-`；初始口令至少12字符、UTF-8不超过72字节，不存明文、不回传口令。首版只创建员工，不提供公开注册或通过状态接口改动管理员。

**问题与解决**：错误密码、账号不存在和停用/删除统一401；身份存储故障返回503，不能伪装成输错密码。登录请求只收固定长度的URL编码表单，最大4KB，不允许查询串携带口令。私有POST最大16KB且要求已知长度；将来文件上传须独立设计文件边界，不能直接复用此限制。敏感控制器均用`@NoPayloadLog`，实体和请求字符串也不输出口令/散列。

**还能怎样优化**：当前为单节点会话及内存限流；部署多实例前再评审共享会话、网关可信来源、分布式限流、企业NAT下的限额和统一撤销。管理员首次口令交付、员工自主改密/找回、MFA和实名核验流程未实现，不应冒充账号治理全部完成。

### 2.4 资源授权与安全视图

**为何这样选**：资源必须在读取时限定范围；不先读全表再靠前端隐藏，也不把管理员或“看得见同事”当成私有内容授权。Mapper只提供带范围的查询，不继承可无条件读取资源的BaseMapper。

**代码与数据如何流转**：`EnterpriseResourceController`取得可信成员，`EnterpriseResourceServiceImpl`复核后调用`EnterpriseResourceMapper`。会话同时限定企业、成员、账号、非访客和未删除；消息从所属会话继承范围；任务锚点同时关联同企业会话及该会话消息。知识空间必须存在有效成员授权，或当前有效直属部门授权；文档还要求企业与空间一致且未删除。文档视图不返回`file_path`。

**问题与解决**：不存在和无权统一业务码404，避免探测其他企业资源。管理员没有默认旁路。撤销空间授权、停用空间/部门或删除父会话后，相应读取拒绝。所有输入使用`#{}`绑定，拼接仅用于编译期固定SQL片段，不使用`${}`或模型生成SQL。

**还能怎样优化**：上传、原件、引用、历史版本、导出和正文检索需要后续独立实现；正式检索还必须检查发布版本、生效/失效和外发许可。当前文档解析状态不是发布状态，不能凭元数据接口直接把文档送入模型。任务锚点需未来执行器在受理事务中写入，本轮没有受理、执行或恢复接口。

## 3. 接口与前端接入契约

| 方法与路径 | 输入/作用 | 安全要求 |
|---|---|---|
| `GET /api/auth/csrf` | 初始化会话，返回`headerName`和`token` | 无需登录；不把token记日志；客户端保留Cookie |
| `POST /api/auth/login` | URL编码表单`username`、`password` | CSRF头＋Cookie；不是JSON登录；成功后重新获取CSRF |
| `GET /api/auth/me` | 返回当前账号编号 | 真实登录；不返回口令、权限凭据或完整账号 |
| `POST /api/auth/logout` | 退出当前会话 | CSRF；会话失效并清Cookie；再次使用需重新初始化 |
| `POST /api/auth/revoke-sessions` | 递增本人认证版本 | CSRF；旧登录下一次请求失效，含其他会话 |
| `POST /api/enterprises/{enterpriseId}/employees` | JSON`username`、`password`，返回创建的账号/成员/企业编号 | 该企业管理员；事务开户；已有同名账号不被自动纳入 |
| `POST /api/enterprises/{enterpriseId}/employees/{memberId}/status` | JSON`status`为整数0有效/1停用/2离职 | 该企业管理员；只操作员工；拒绝缺失、小数、字符串和布尔值 |
| `GET /api/enterprises/{enterpriseId}/conversations/{id}` | 会话最小视图 | 仅本人在所选企业的会话 |
| `GET /api/enterprises/{enterpriseId}/messages/{id}` | 消息视图 | 从本人获准会话继承归属 |
| `GET /api/enterprises/{enterpriseId}/knowledge-spaces/{id}` | 空间元数据 | 明确成员或有效直属部门授权 |
| `GET /api/enterprises/{enterpriseId}/documents/{id}` | 文档元数据 | 空间授权＋企业一致；不含原件路径 |
| `GET /api/enterprises/{enterpriseId}/tasks/{id}/reference` | 任务编号、会话编号、消息编号 | 本人会话且消息关联一致；不表示任务执行状态 |

全部返回`Result<T>`。沿用原约定：MVC业务异常HTTP200、`code`为400/401/404等；安全过滤器的401/403/413/429/503同时使用对应HTTP状态及Result。前端必须同时检查HTTP和`code`，不能把HTTP200直接当成操作成功。BIGINT编号沿用全局Long字符串序列化，避免浏览器丢精度；`timestamp`仍为数字。

测试库真实样例（仅摘录已验证字段）：账号`owner`对应账号1，在企业1是成员101，在企业2是成员201。登录返回`code=0`和账号1；在企业1读取会话1001，标题为“本人甲企业会话”；读取同企业他人会话1002或乙企业会话2001，业务码均404。在企业2读取2001才成功。管理员账号3读取1001仍404。任务9003错误关联其他会话的消息，读取404。

会话期限：闲置30分钟，绝对8小时；成功登录重新签发起点，读取/刷新不延长绝对期限。Cookie仅跟随请求，HttpOnly、SameSite=Lax；prod设置Secure，部署需HTTPS和明确的前后端来源，优先同源代理。上述是员工登录会话，不是访客日切或后台任务时限。

默认单节点登录限额：每直连地址每分钟10次、全局每分钟120次；可通过`LOGIN_PER_ADDRESS_PER_MINUTE`、`LOGIN_GLOBAL_PER_MINUTE`调整，全局不得小于单地址，最大100000。计数状态最多4096地址，固定窗口过期清理；不信任客户端转发头。固定窗口边界可突发，不等于平滑令牌桶或完整生产防刷。
