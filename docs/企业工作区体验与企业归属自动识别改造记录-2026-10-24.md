# 企业工作区体验与企业归属自动识别改造记录

日期：2026-10-24。范围：用户已同意连续完成的企业归属、企业页面体验、导航和回归；联网问答保留主体界面，不新增依赖或数据库结构。

## 一、为什么这样做，可以用什么替代

企业内部员工通常只需要登录和使用知识，不应该先理解数据库企业编号。现在从可信登录身份查询有效成员关系，单企业自动连接；确有多个企业归属时按名称选择。企业编号仍在接口内部传递，但不再作为员工必填项。

没有使用“默认企业1”：它会在换库、增加企业或迁移账号时选错上下文。也没有依赖前端保存的企业信息作为授权依据：客户端可以被修改，最终仍由服务端逐次核验账号、企业、成员和空间授权。

工作台负责导航和入门，企业问答负责提问和核对出处，知识空间负责资料治理。去掉顶部重复企业问答入口，企业页面不再展示公开问答历史。相较继续堆叠表单，当前使用对话区、状态提示、问题分项卡和来源侧栏，使用户先看到问题与结果，再按需展开技术信息。

开工曾检索GitHub上的Dify/LobeChat界面方案，但工具未返回可用正文；本轮没有据此复制开源代码，也没有引入新组件库、字体、图片下载或依赖。

## 二、怎么实现，代码和数据如何调用

登录 → 前端读取`GET /api/auth/me` → 服务端复核账号及认证版本 → 参数化查询有效企业成员关系 → 再复核账号 → 返回企业名称和角色 → 页面加载获授权空间。读取归属只是选择工作区，不替代资源授权。

接口保留`userId`，增加`enterprises`。示例是虚构数据，编号沿用现有Long转字符串约定：

```json
{"code":0,"data":{"userId":"25","enterprises":[{"enterpriseId":"1","enterpriseName":"知序·虚构企业","role":"ADMIN"}]}}
```

## 三、可能遇到的问题和本轮处理

| 情况 | 实际处理与限制 |
|---|---|
| 账号无企业或无空间授权 | 显示联系管理员/知识负责人，不能直接提交问题；不猜测企业编号。 |
| 一个账号属于多个企业 | 先按企业名称选择，切换时清除旧空间及问题上下文；服务端仍按所选编号核权。 |
| 前端已更新、后端仍是旧版本 | 缺少enterprises时明确提示重启最新版后端，不回退手填编号。 |
| 目录查询失败、账号过期或查询期间撤销登录 | 查询失败可见，拒绝过期身份；归属结果不保证之后始终有效，资源接口继续核权。 |
| 恶意企业名、空间名或资料正文 | Vue文本插值展示，不当HTML执行；测试夹具包含攻击字符串，截图出现其文本不代表脚本执行。 |
| 断网、超时、写结果未知 | 沿用已有有界请求、原任务恢复与未知写结果核对；不新增自动重试或无限等待。 |
| 手机屏幕 | 问答与来源变单栏，装饰减少；320/390/768/1440像素检查水平溢出。 |

本轮也保留真实失败过程：新增服务方法使匿名测试替身编译失败，补上委托；业务异常构造参数不匹配已修正。Mockito对已抛异常方法再次when设置会提前抛错，改用doReturn。旧UI测试依赖“1.问题”文本，新界面是01卡片，改为逐项校验问题内容和展示顺序，没有删除顺序断言。

## 四、后续怎么优化，代价是什么

1. 企业归属很多时可做带权限版本的分页目录；当前上限100符合首版页面约束，不能偷偷截断。分页需处理选择项不在当前页和刷新后归属撤销。
2. 可接企业SSO减少重复登录，但仍须将外部身份映射到本地成员和资源授权；SSO成功不等于获准访问所有知识。
3. 可缓存归属减少数据库读取，但必须有认证/权限版本、撤权失效和短期陈旧处理；本轮未加Redis或缓存，不拿性能换撤权可见性。
4. 视觉效果可继续做可用性走查和键盘/读屏专项验收；本轮使用语义化控件、标签和响应式检查，不声称已通过完整无障碍认证。

知识点：Session、认证版本失效、租户上下文与资源授权的区别、参数化SQL、最小响应投影、Vue computed/watch与异步作用域隔离、中文输入法事件、渐进展示、响应式布局和文本XSS防御。本轮没有接入MCP、OCR或新的模型/Redis服务。
