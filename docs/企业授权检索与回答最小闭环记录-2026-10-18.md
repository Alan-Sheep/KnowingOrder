# 企业授权检索与回答最小闭环记录

## 1. 交付与证据边界

本轮在现有文字入库上接通“企业登录 → 获授权空间 → 当前有效发布片段 → 回答 → 引用重新授权读取”。沿用Java 17目标、Spring Boot、MyBatis、MySQL、Vue和已有模型客户端，未增加依赖、数据库迁移或独立服务。未重放schema或修改已有数据归属。

**已实现**：MySQL关键词召回、当前发布与授权过滤、两种数据边界、虚构资料多问模型回答、引用校验、单节点有界执行及页面。**已验证**：离线回归、真实MySQL与已配置中转模型的单维护者页面闭环。**未完成**：向量语义召回、企业黄金集、真实企业资料模型外发、多轮持久上下文、持久任务/重连、分布式配额和生产容量。不能以本记录宣称全部D阶段或生产验收完成。

用户仅批准虚构资料与合成问题外发。默认`LOCAL_EVIDENCE`只显示原文；只有服务端配置的专用测试空间使用`SYNTHETIC_MODEL`。客户端不能自行开启许可。模型调用一次完成结构化作答，无公开搜索或自动重试。GitHub成熟方案检索本轮未取得可用正文，不声称已验证或采用Spring AI/LangChain4j实现。

## 3. 面试四方面：为什么、怎么流转、故障、优化

| 单元/知识点 | 为什么选、替代方案 | 具体实现与风险 | 优化方向及代价 |
|---|---|---|---|
| 关键词RAG检索基线 | 复用已有MySQL，先得到可追溯基线；暂不增加Embedding和向量服务 | 中文双字词、拉丁词、停用词，最多48词；绑定LOCATE并按命中词数排序，最多24候选/6片段。不是语义理解，近义表达与长尾问题容易漏召回 | 黄金集比较关键词、全文、向量及混合召回；增加模型/索引成本、版本一致性和权限过滤治理 |
| 检索接口/依赖倒置 | `KnowledgeRetriever`让服务不绑定召回存储；直接在Controller写SQL会混淆身份、召回和回答 | 当前唯一实现为关键词；后续替换必须仍满足授权与版本契约，不能假设接入任意库只改配置 | 有证据后加适配器与契约回归；避免无用空实现 |
| 授权下推SQL | 全量读后在Vue隐藏会泄露原文与数量；只看管理员角色不能表达资源授权 | 同时限定有效成员、企业、空间、明确授权、非删除文档、当前PUBLISHED/READY版本、生效区间及位置；维护者也不能以草稿作答 | 查看执行计划和真实数据分布再优化索引；LOCATE可能扫描较多行，LIMIT不限制扫描量 |
| 有据生成与多问题 | 一次模型调用减少往返；分问各调一次会增加费用且更难共享总时限 | 最多三段，连续原文拼接完整覆盖问题；每项区分ANSWERED/PARTIAL/NO_EVIDENCE/CONFLICT。不把排序决定推给用户；当前按原文展示，无独立依赖调度器 | 用坏例测拆问与必要前置推理；复杂编排另加有界规划，不把一次JSON回答称多Agent |
| 引用与资料充分性 | 只有链接/编号不能证明引文存在；不够就答一部分，优于编造制度 | 引文须为所选片段连续原文；来源号、状态、缺口、问题覆盖和冲突至少两来源由程序校验 | 原文存在不证明结论语义成立；加黄金集、引用蕴含评估和人工反馈，须量化额外调用代价 |
| 外发白名单 | 模型连通不等于企业批准；默认不外发，专用合成空间开放 | 启动环境变量只允许企业:空间对；送模型前、返回前重查成员/权限/证据。已经外发的数据无法撤回，复核不等于跨系统原子授权 | 企业许可、供应商数据条款与部署方式另审；空间白名单不是内容分类器，严禁把真实资料放入该空间 |
| 并发与截止时间 | 无限队列/重试会占满资源；两执行者和零排队先控制本机影响面 | SynchronousQueue+AbortPolicy，第三条503；30秒总等待、Future取消与中断。SQL单次2秒配置不等于所有驱动都能硬中断；上游可能继续计费 | 持久任务、每成员配额、跨节点限流和驱动取消验证；需要共享状态及容量数据，不直接堆Redis |
| 页面与安全 | 服务端状态直达用户，避免日志报错而界面一直等待；纯文本避免HTML执行 | 预告实际外发模式、两问独立卡片、最多十条；35秒结束客户端等待，无自动重发；每次点引用重新请求 | 刷新历史、续问合并、SSE恢复、登录撤销跨页同步需独立实现；页面中已展示的文字不可能从用户记忆中收回 |

涉及的服务/知识：MySQL和MyBatis参数绑定、Spring Security Session/CSRF、Spring Validation、Java不可变record、Executor/Future/截止时间、Prompt注册、RAG检索增强与引用校验、Vue响应式和AbortController、Vite代理。复用中转Responses客户端；未使用MCP、Embedding、Redis或OCR。

## 4. 调用链与真实数据

1. `KnowledgeAnswerPanel.ask()` → `enterprise.answer()`先获取CSRF，携带Session发JSON；不提交memberId或外发开关。
2. `KnowledgeAnswerController.answer()` → `KnowledgeAnswerService.answer()`建立30秒预算，提交有界执行者。
3. `execute()`核成员和空间 → `retrieve()`授权SQL召回 → 过滤重叠并截取六片段。
4. 无资料直接NO_EVIDENCE；默认本地返回EVIDENCE_ONLY；专用合成空间再次核权后`compose()`调用`ChatModel.call("knowledge", ..., 3000, deadline)`一次，复用Responses适配。
5. 结构/引文校验后再复核权限与片段；返回Result。模型或格式失败明确MODEL_UNAVAILABLE，保留获准原文，不换公开搜索。
6. 点击引用走`evidence()`重新查当前权限和有效版本；失效时拒绝，不使用旧原文作兜底。

## 5. HTTP与失败契约

令`A=/api/enterprises/{enterpriseId}/knowledge-spaces/{spaceId}/answers`。JSON统一Result，Long编号为字符串。

| 请求 | 输入/结果 |
|---|---|
| GET A/mode | 核权后返回LOCAL_EVIDENCE或SYNTHETIC_MODEL；无模型调用 |
| POST A | `{"question":"加班餐补每天上限多少？申请需要谁审批？到账时间是多久？"}`；1—1200字符，需Session/CSRF |
| GET A/evidence/{chunkId} | 返回当前可读Evidence及UTF-16坐标/行号；不返回磁盘路径或摘要 |

Answer含mode/status/message/parts/evidence/elapsedMs；Part含id/question/status/paragraphs/gaps；Paragraph含text/citations；Citation含sourceId/evidence/quote。无证据/模型失败仍是有明确业务状态的响应，不等同生成成功；前端同时校验HTTP与Result.code。401登录失效、404无权或不存在、409资料变化、503饱和、504超时都有安全提示。

业务异常沿用GlobalExceptionHandler；新入口NoPayloadLog和Mapper INFO避免原文参数入日志；模型沿用prompt_id/耗时日志，服务追加模式、状态、证据数、耗时。不记录问题正文、引文或模型原始输出。完整生产指标、错误分类看板和告警仍待建设。
