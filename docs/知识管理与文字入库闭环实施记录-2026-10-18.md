## 3. 为什么这样选、替代方案与优化

| 单元 | 为什么这样做 | 替代方案及当前不选原因 | 可优化方向与代价 |
|---|---|---|---|
| 授权目录与维护 | SQL同时限定身份、企业和明确授权；管理员不自动拥有全部知识 | 全量读再在Vue隐藏会泄露标题和总数；仅检查角色无法表达资源授权 | 数据多后看MySQL执行计划，评估游标；改变分页契约，COUNT与记录当前不是同一跨请求快照 |
| 私有本机原件 | 用户已选，本地小文字无需外部存储或解析费用；不注册静态公开目录 | 公共静态URL绕过撤权；对象存储当前增加部署与权限治理成本 | 多节点前改受控对象存储；需要迁移、备份、签名期限和撤权策略 |
| 文档与版本分离 | 新草稿失败不覆盖合法旧发布版；原件不可变，状态可变 | 原行覆盖无法追溯；只用一个status混淆解析和发布 | 索引构建引入独立任务及版本指针，不把本次文字发布直接当向量发布 |
| 先TXT/MD | 用JDK严格解码、原文和位置可核对，不先装庞大解析组件 | PDF/Word需要格式解析与额外安全边界；不能按扩展名直接当文字 | 加解析适配器并保留页/章节位置，增加格式故障集；不引入OCR |
| 长度与段落结合 | 1000字符上限、120重叠，段落/换行优先，避免emoji断开 | 纯固定长度容易破坏结构；语义切分需模型成本及企业外发授权 | 用真实语料比较召回和引用后调整；当前参数是起点，不声称最佳或token长度 |
| 事务加版本检查 | 空间锁串行化维护，revision防旧页面覆盖，片段与READY一同提交 | 单靠前端禁用无法防多标签/多节点；仅Redis锁不保障DB状态一致 | 大文件改有界后台任务；降低锁粒度需重新验证授权竞态、死锁和幂等 |
| 上传幂等 | 范围唯一UUID加参数/内容指纹，换参409，响应丢失可原编号重试 | 文件名去重会误合并；只看SHA可能错误合并不同标题/有效期 | 保留幂等期限、核对接口和跨重启恢复需另行设计，不提前加Redis |
| 有界等待与反馈 | 单节点4个入库/原件槽，不排无界队列；前端10秒结束等待，写未知不自动重发 | 无限重试会叠加重复写与资源占用；取消Fetch不保证数据库回滚 | 网关、驱动、磁盘与后台任务总时限需上线前独立验收；本轮不承诺端到端硬10秒 |

## 4. 具体代码与数据流

主入口：[KnowledgeDocumentService](../backend/src/main/java/com/ragqa/service/KnowledgeDocumentService.java)的`upload()`第118行、`parse()`第188行、`lifecycle()`第231行、`original()`第106行。
解析入口：[Utf8TextParser.parse](../backend/src/main/java/com/ragqa/rag/ingest/Utf8TextParser.java)第22行；原件：[PrivateKnowledgeFiles.save](../backend/src/main/java/com/ragqa/service/PrivateKnowledgeFiles.java)第31行。前端组件`upload()`第102行、`parse()`第125行、`lifecycle()`第137行，位于[KnowledgeDocumentsPanel.vue](../frontend/src/components/KnowledgeDocumentsPanel.vue)。

1. 浏览器获取新CSRF，multipart的`metadata`为JSON，`file`为原件；认证主体来自Session，不接受前端提交角色或成员号。
2. `upload()`先维护权检查，再限量读取文件，事务内再次锁空间并核对；幂等命中且指纹一致返回原版本。新请求插文档、随机键保存原件、插版本，默认PENDING/DRAFT。
3. `parse()`先核权取原件，事务外严格UTF-8解析；回到事务重新核权、锁文档并检查revision，按100条批量写片段，最后更新READY与片段数。READY重复解析直接返回，不重复插入。
4. `lifecycle(PUBLISH)`核对实际片段数、生效期与revision，同事务撤回旧发布版并改当前指针。READ成员只看到当前有效发布版；维护者可以治理草稿/历史。撤回不回退旧版。
5. `original()`读前核权，读取后再核验成员、授权和版本；附件返回no-store、nosniff，不公开storage_key、摘要或磁盘路径。

隔离测试实例：`审批细则\n`加重复正文入库为PENDING/DRAFT，解析后产生多个片段；只读成员此前目录总数0，明确发布后总数1，撤回后再次0。输入`正文`产生片段`content="正文", startOffset=0, endOffset=2, startLine=1, endLine=1`。位置是Java UTF-16索引，不是字节或token。

## 5. HTTP契约与错误行为

空间基址`S=/api/enterprises/{enterpriseId}/knowledge-spaces/{spaceId}`；文档基址`D=S/documents`。写入均需Cookie及CSRF。Long编号使用字符串，revision/permissionVersion为安全整数。

| 方法与相对路径 | 输入/结果 |
|---|---|
| GET /api/enterprises/{enterpriseId}/knowledge-spaces | pageNum/pageSize；只含有权空间与总数 |
| POST S/rename | expectedVersion、name |
| GET/POST S/grants | 查看授权；修改传expectedVersion、targetType、targetId、permission、revoke |
| GET/POST D | 文档分页；上传metadata+file |
| GET D/{documentId}、/versions、/versions/{versionId} | 文档与有权版本 |
| GET D/{documentId}/versions/{versionId}/chunks、/original | 可定位片段分页；或二进制附件 |
| POST D/{documentId}/versions/{versionId}/parse | expectedRevision |
| POST D/{documentId}/lifecycle | expectedRevision、versionId、action：PUBLISH/WITHDRAW/DELETE_VERSION/DELETE_DOCUMENT |
| POST D/{documentId}/owner | expectedRevision、ownerMemberId；目标须同企业有效且已有维护权 |

metadata示例：`{"requestId":"00000000-0000-4000-8000-000000000001","documentId":null,"expectedRevision":null,"title":"企业制度","validFromMs":null,"validUntilMs":null}`。新增版本必须指定documentId及当前expectedRevision；有效期为UTC毫秒，前端从当前设备时区转换，不作为可信服务端时钟。

JSON仍为`Result<T>`；业务400/404/409可能HTTP200，客户端检查两层状态。401引导重新登录并清私有展示；无权与不存在统一404；409先刷新；413缩小文件；503处理繁忙或存储故障，手动重试；504解析超时。缺少multipart part为400，错误媒体类型为415。未知服务异常不展示SQL、路径或原始消息。

单个原件最多1MiB，完整multipart最多2MiB；未知Content-Length不受理。其他私有POST维持16KiB。解析最多50万UTF-16字符、1000片段，切分循环检查5秒期限；数据库写事务10秒。事务期限不等于操作系统文件IO可被强制取消，不能据此宣称上线延迟SLA已达标。

## 6. 故障、回滚与上线前剩余边界

- 版本插入失败：数据库回滚文档/版本，确认回滚后仅清本次原件；提交结果未知时保留原件供核对，不能误删已提交版本的文件。
- 原件写中途失败：清理本次CREATE_NEW创建的残片；清理失败给安全错误，不暴露路径。SHA256验证内容完整性，不代替权限或加密。
- 片段写到一半失败：整事务回滚，不留下半套片段；PENDING可人工重试。非法UTF-8/解析超时/原件异常保存FAILED及安全分类；不保存原文或异常堆栈到版本表。
- 并发相同上传只提交一个版本/原件；并发解析只提交一套片段。空间锁是当前正确性优先的粗粒度方案，吞吐量尚无负载证据。
- 已发布版本须先撤回再删版本；整文档逻辑删除清发布指针。逻辑删除保留原件，不等于已实现物理删除或保留期限治理。
- 旧文档元数据入口拒绝owner非空的新文档，防草稿/撤回标题旁路；历史owner为空记录保留兼容，不自动迁移、发布或提供原件。
- dev父日志为DEBUG，已为KnowledgeDocumentMapper、KnowledgeManagementMapper、KnowledgeSpaceMapper显式设INFO；HTTP测试验证NoPayloadLog，关闭参数输出，不把正文、令牌或原件键放日志。
- 前端上传未知结果保留内存中的原File、参数和UUID，重试不换参。刷新/关页会丢失内存，之后先核对数据库目录，不能宣称已实现跨刷新幂等恢复界面。
- 尚需：进程崩溃孤儿原件核对、磁盘容量/留存及备份恢复、生产ACL/HTTPS/代理限制、MySQL锁及故障复验、多节点容量/限流、真实企业语料质量评估。单节点槽不等于分布式配额，未部署Redis。
