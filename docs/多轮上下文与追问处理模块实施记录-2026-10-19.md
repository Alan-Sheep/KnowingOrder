## 3. 为什么用这个方法，有什么替代

**快照而非执行时重查。** 同一会话可有两条在途问题，任务调度和模型完成顺序不同；执行时重新查历史会把后来的状态带进旧任务。现在在原受理事务中读取最近完整原问题窗口，并写`rag_knowledge_context`。重复POST直接返回原任务，不更新快照。旧任务没快照时只按原问题处理，不事后补历史。替代的会话序号能进一步处理同毫秒和时钟回拨，但需要更大迁移与并发设计，本轮保留同毫秒排除的保守边界。

**两次受控调用而非自由改写。** 首轮只给关系和编号，第二轮不接收首轮解释，只看原始上下文和所选编号，减少沿用首轮辩护。代价是最多增加两次调用、输入重复与延迟；它不是独立模型投票或语义正确性证明。两次合计5秒、各最多500输出Token，回答最多3000输出Token，合计最多3次调用；这些是初始资源保护值，不是费用硬上限或生产SLA。

**原文分字段而非拼成新问题。** 当前问题不改写，历史只作话题线索；当前与历史问题分别走同一授权检索，先保留当前候选再按编号去重补足到6段，同编号完整快照冲突直接失败。这里不调用既有独立改写/融合实验类，不把历史问题当制度依据。替代的仅检索改写句可能丢掉否定、时间、对象，已有7条漂移反例尚未解决。

**不确定时先显示原文。** UNRESOLVED或UNAVAILABLE不会再调用回答模型猜对象；当前问题有命中则EVIDENCE_ONLY，无命中则NO_EVIDENCE，并显示原因。不是让员工选择“哪个问题优先”，也不要求先取消其他任务。员工可继续补充业务对象；系统不把“缺少上下文”和“公司没有规定”混为一谈。

## 4. 数据流与实际离线样例

受理：可信账号→成员/空间授权→成员行锁→UUID幂等检查→创建任务→读取授权历史→同事务保存完整上下文和SHA-256→提交。快照插入失败，任务及本次新会话一起回滚；事务中不调用外部模型。

执行：原任务剩余预算→claim RUNNING→读取本人快照并核对任务/会话/原文/摘要→许可检查→候选→复核→原问题授权检索＋可选话题授权检索→分别传当前问题/话题/来源→严格引用和问题覆盖校验→再次核权及核对来源→终态CAS。任务取消或过期后，迟到结果不能覆盖终态；本地取消不保证供应商退款或立即停算。

离线模块测试先保存历史“加班餐补上限多少？”，当前提交“那找谁审批？”。固定替身给出FOLLOW_UP及ACCEPT后，回答payload中的question仍是“那找谁审批？”，antecedentQuestion单独是历史原话。合成制度为“加班餐补每人每天30元，申请需主管审批。”，返回“申请需主管审批。”及实际连续引用；任务结果可通过本人历史读取。此样例证明调用链和契约，不是模型自主理解的真实成绩。

若替身返回UNKNOWN，则当前问题“那餐补找谁审批？”只得到EVIDENCE_ONLY、空paragraphs和“未能可靠确定历史话题”的可见提示；不会再调用回答模型。文本中的script/指令仍按原数据传输及纯文字展示，不因此宣称完全消除提示注入。

## 5. 问题、处理与优化代价

| 问题 | 当前处理 | 尚有边界或优化代价 |
|---|---|---|
| 同毫秒/时钟校正 | 历史SQL不取与当前同毫秒问题；历史候选自身同毫秒不靠UUID推顺序 | 没有会话受理序号；不能说解决了任意时钟回拨 |
| 重启/历史状态变化 | 快照只插一次，PENDING恢复读原快照，RUNNING仍不自动重放 | 没有跨节点执行租约；未做真实重启及多节点压测 |
| 模型空值/坏JSON/401/429/持续宕机 | 严格解析、一次失败即降级、不回灌失败正文、不重试 | 用户可见失败不等于上游一定停止计费 |
| 5秒阶段和30秒父截止 | 两轮同一个limitedTo阶段实例，复用原父预算；父截止或线程中断继续失败 | DB连接池/驱动等任意阻塞的硬中断仍须生产故障验证 |
| 模型调用中撤权/快照变化 | 解析后重核权并重读比较完整存储快照；存储失败不吞成空历史 | 最后复核后仍有并发窗口，已发数据无法收回；外发许可不能靠Prompt产生 |
| 误选合法历史 | 二次复核可返回REJECT/UNKNOWN，全部绑定原上下文 | 同配置模型可能相关性失败；没有真实错选率/误拒率成绩，默认关闭 |
| 附加候选与原文不一致 | 同编号不同完整快照409；引用生成前后核权 | 相关性、引用存在和语义支持是不同指标，不保证每条候选适用 |
| 日志泄漏 | 快照留在已设INFO的WorkspaceMapper，toString隐藏正文；固定错误提示 | 不等于完成全系统敏感日志审计；后续新增Mapper也要同样检查 |
| 快照留存 | 与本人任务逻辑关联、不对外增加读取入口 | 自动留存清理、删除策略和完整分页仍待治理，不能称已完成合规留存 |

可优化方向按实际数据触发：独立人工标注集与不同模型复核对照、中文本地模型、会话序号、批量授权复核、精确Token预算和指标。都需要新成本/质量/一致性验证，不为“高级感”引入Redis、MCP、MQ或Agent框架。
