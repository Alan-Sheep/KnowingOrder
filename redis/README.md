# Redis 配置目录

本目录预留给 Redis 配置与部署说明，当前尚未安装服务或接入后端缓存。

## 知序中的规划用途（2026-10-17）

企业知识库与业务问答为主，后续按需要评估缓存、调用预算、并发接纳、幂等协助和任务进度的共享状态；本轮只补说明，未选定客户端、部署方案或新增配置。持久财务事实、参与确认和额度结算仍以数据库的事务、唯一约束及可追溯记录为准，不能仅靠Redis锁或缓存保证正确。

- 知识缓存必须区分企业、资源权限范围、文档/索引版本及必要查询参数，读取前复核权限；不能只按问题文本作为缓存键。
- 文档撤回、成员撤权、规则变更需要失效或版本隔离，旧缓存不得绕过授权。敏感正文、密钥、票据原件和完整身份凭据不随意放入缓存。
- TTL、容量、穿透/击穿防护及并发控制参数须根据实际数据和测试确定；当前不沿用旧公开搜索缓存的24小时/6小时作为企业默认值。
- 缓存故障可退回受限数据库或检索路径；认证、硬额度和关键幂等控制不可用时须拒绝相关动作，不绕过限制启动付费调用或结算。
- 上线前验证跨企业隔离、撤权、并发、故障恢复、积压及内存告警；日志只记录脱敏请求标识、命中率和耗时，不记录敏感缓存值。

后续 Redis 配置与后端 `../backend/`、前端 `../frontend/` 分别维护。密码由部署环境注入，运行数据与日志不提交到仓库。
